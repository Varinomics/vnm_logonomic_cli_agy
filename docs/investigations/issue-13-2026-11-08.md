## Reproduced baseline defects

The selection regressions control native exit and wrapper completion order.
A and B are synthetic root identities; returning to A has a fresh activation nonce.

| Baseline experiment | Required result | Observed loss |
|---|---|---|
| Admit A; hold B's wrapper; capture returned A; reap native exit 7; release B | A, B, A admitted in order | A, B only; queued return to A discarded |
| Admit A; pause the bridge at its wait boundary; buffer B; exit original child 7 while a descendant retains the logger | A, B admitted; original exit status preserved | A only; buffered B discarded |

The first failure used the unchanged baseline bridge. The second used a baseline
bridge linked with the test-only native-wait tracer; `waitid(..., WNOWAIT)` proved
the original child's exit while leaving production `waitpid` as its reaper.

Packaged baseline inspection also returned `ABSENT` for the unsupported invocation
`agy ""`. More concretely, with `REMOTE=true`, launcher argv
`bash -lc 'agy --remote-agent=$REMOTE'` returned the following at `interactive-resume@3`:

```text
host_status=success
payload={"availability":"absent","request_digest":"d13041b7ab0da44d2a83e10b79fd4a0eee815f40a071e77540063c0a3a4ab4e5"}
exited_by_signal=0
```

An unresolved shell expression cannot establish local conversation absence.
No packaged adapter crash was reproduced; the defect was the incorrect result.

## Implemented correction and adapter validation

Normal native exit now drains at most four currently available log chunks and
gives all captured selections one shared five-second settlement grace window.
In-flight and queued deliveries retain their keys, order, and activation nonces.
The bridge preserves the original exit status and does not wait for descendant
logger EOF. Cancellation retains SDK wrapper custody through termination/reaping;
the grace window is not a hard wall-clock guarantee of OS process settlement.

Literal options are validated before reading the local/remote switch or adding
the local selection observer. Unsupported inspection stays `UNKNOWN`; ordinary
preparation retains the original launch, and exact resume refuses unsupported recipes.

The corrected exit tests pass for delayed B with queued return to A, a blocked
host, and buffered B after original-child exit with a descendant retaining the logger.
Packaged inspection passes at versions 3 and 4 for unsupported/expanded/remote and
literal local cases, checks exact request acknowledgment, and preserves version 3's
availability-only response. These are adapter contracts, not native interaction gates.

The full Linux CTest run passed **7/7 in 46.17 s**: `agy_continuation_tests`,
`agy_provider_tests`, `agy_usage_scan_tests`, `agy_resume_bridge_tests`,
`agy_helper_tests`, `agy_package_validation`, and `agy_package_conformance`.
After the final test-only expanded-remote row and diagnostic update,
`agy_provider_tests` passed again **1/1 in 0.50 s**; production sources were unchanged.
No Windows rerun or hosted workflow dispatch is claimed by this investigation.

## Real native probe: onboarding gate, no qualification

The official installer manifest supplied the unmodified Antigravity **1.5.3** for Linux x64.
The downloaded archive matched its manifest SHA-512; extracted executable SHA-256:
`7ca212748ca0dfda718efbc39a776a104472e7e9344d4b6ea147c543684f96a3`.
[Release archive](https://storage.googleapis.com/antigravity-public/antigravity-cli/1.5.3-6604829099950080/linux-x64/cli_linux_x64.tar.gz).

The Python PTY used disposable HOME/XDG/tmp directories and a nested non-Git cwd,
an explicit environment allowlist, `modelProvider: gemini`, a nonsecret dummy
`GEMINI_API_KEY`, and `GOOGLE_GEMINI_BASE_URL` plus HTTP(S) proxies pointing to a
loopback sink that never forwarded requests. `AGY_CLI_DISABLE_AUTO_UPDATE=true`.
No existing profile, account credentials, consent flags, or fake histories were copied.

Literal short evidence, with log timestamps/prefixes omitted:

```text
1.5.3
Auto-update disabled via environment variable AGY_CLI_DISABLE_AUTO_UPDATE
ChainedAuth: authenticated via gemini_api_key (effective: gemini_api_key)
Terms of Service & Data Use
```

Exactly one Enter confirmed the displayed theme. At the consent screen, no input
accepted or toggled consent. Ctrl+C followed by SIGTERM settled the fixture with
exit 0 after 23.306 s. No prompt, slash command, root selection, or model-endpoint
request occurred. Ten other CONNECT attempts were refused at loopback (four
`www.gstatic.com:443`, six `play.googleapis.com:443`); none were forwarded.
The empty-identity redraw is not identity confirmation; theme-preview text is not a prompt.

## Remaining gates

Real idle `/clear`/`/new`, successful `/resume` and cancellation, A → B → A,
startup resume/history acceptance, `/projects`, and `/fork` remain unqualified.

and desktop retention/Notes association. This probe establishes a consent gate,
not lack of native support. See the [native contract](../native_conversation_contract.md)
